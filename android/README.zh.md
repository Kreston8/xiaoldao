# 小灵岛 for Android

[English](README.md) | 中文

这个仓库是「小灵岛」（xiaoldao）独立的主仓库：一个原生 Android 通知岛。
灵感来自 islandcn（MIT，(c) 2026 Leo，那是一个 Next.js 站点加一套 shadcn registry，不是 App），
实现全部重写，没有复制它的任何代码（见 NOTICE）。屏幕顶部一颗黑色胶囊，高度固定，宽度随内容变长变短，
不会弹开也不会自己收起。

它替换掉了更早的 WebView 外壳，页面一个都不加载。App 里只有两个可选的 HTTPS 请求——逐行歌词和
气温——下面都写清了它们的边界。

## 显示什么

八类卡片：前四类由 `ContentParser` 从标题、正文和应用名判断，其余四类各自有来源。

| 类型 | 触发 | 卡片 |
|---|---|---|
| 微信 | `com.tencent.mm` 的通知 | 头像 + 发送者 + 消息 |
| QQ | `com.tencent.mobileqq` 的通知 | 头像 + 发送者 + 消息 |
| 取件码 | 短信里带「取件码/取货码/提货码」且附近有编码 | 快递点：取件码（`菜鸟驿站：1-2-3456`），点一下跳到那条短信 |
| 外卖 | 「预计 12:35 送达」「还有 18 分钟」 | 每 15 秒刷新的倒计时，按平台开关 |
| 待办 | 小米笔记 / 笔记类应用的通知 | 标签 + 待办文字 |
| 来电 | 通话状态回调 | 标签 + 号码 / 未知号码，点一下开拨号盘 |
| 闹钟 | 系统下一个闹钟，提前 15 分钟 | 标签 + 07:30 + 还有 N 分钟响铃 |
| 音乐 | 正在播放的媒体会话，且桌面在前台 | 46 dp 横条：封面 + 一行歌词，逐字点亮 |

普通通知、验证码、导航现在一律不弹——这是按需求删的，让这八类以外的 App 完全插不进来。

每张卡片都是同一个固定的 46 dp 高度，只有宽度随内容走：一个图标、一行粗体、一行正文。图标就是发通知那个
应用自己的：先取大图标（微信、QQ 把联系人头像放在这里），再取 `MessagingStyle` 里的 `Person` 头像，再退回
应用图标，最后才用状态栏小图标——所以一眼看得出是哪个 App 来的。这个高度只放得下两行，所以可复制的
取件码挪进了标题行，倒计时则顶替正文行，而不是硬塞第三行。胶囊从 250 dp 起，句子长就先加宽到屏幕
边缘，还放不下才左右滚动；歌词行例外，因为逐字高亮要独占它。

**双击**取件码卡片只复制码本身——`1-2-3456`，不带「菜鸟驿站：」前缀；原通知仍留在通知栏，复制不会把东西
弄丢。**左滑**是永久关闭这一条：同一条通知之后再也不会重新上岛，服务重启也不会；左滑闹钟卡片还会同时取消
这一次闹钟后面还没出现的提醒档位。

### 蓝牙设备电量 —— 2.16 起已删除

**这块功能已经删掉了。** Android 没有公开的配件电量 API，所以 2.16 把芯片和 `BLUETOOTH_CONNECT` /
`BLUETOOTH_SCAN` 两个权限一起删了。下面保留的是「为什么这些路都走不通」的记录；
如果你看的是更早的 release，那些版本里它还在。

打开「蓝牙设备电量显示」后，胶囊最右端按设备显示小方块：上面是设备图标，下面是它自己上报的电量百分比，
最多同时显示 3 个设备。每台设备在两级开关里还有自己的一个开关，关掉某一台只影响它：不画方块、也不再为
它读 GATT。播放音乐时歌词条上一定会有电量，不管这一个开关怎么设——那正是最想知道电量的时刻；胶囊会随
之变宽，而不是把文字挤掉。

Android 没有公开的配件电量接口，所以电量按三步依次尝试，哪一步先答就用哪一步：

1. 隐藏方法 `BluetoothDevice.getBatteryLevel()`——就是系统设置里显示的那个数；它在灰名单里，部分 ROM
   会返回 -1 或直接抛异常；
2. 系统自己的 `BATTERY_LEVEL_CHANGED` 广播，设备上报时发（一般是连上的那一刻），读出后缓存并持久化；
3. GATT 读标准电量服务（`0x180F`/`0x2A19`），只对 LE 和双模设备，每个地址 10 分钟最多读一次，读到
   立刻断开连接。

要知道的后果：纯经典蓝牙耳机没有 GATT 服务，只有前两步能答；从没上报过的设备保留图标、数字显示 `--`，
因为手表上写一个错的电量比不写更糟。

### 桌面常驻

打开「桌面常驻」后，屏幕上没有别的卡片时，桌面上会多一条窄胶囊，内容就是你在设置里打开的那几项：

- **天气温度** — 当前气温加一个按 WMO 代码选的天气图标，例如 `23°`。需要先在 App 里填一个城市名；
  没有定位权限，也不用 GPS。地名服务一次问十个中文候选，逐个打分（名字完全相同 > 区县 `admin3` >
  城市 `admin2` > 省 `admin1` > 前缀命中），取分数最高的那个，所以「杭州 西湖」会落到西湖区而不是
  杭州市；真正解析到的位置会显示成「已定位到 …」，因为 Open-Meteo 并没有收录国内每一个区。
- **空气质量 AQI** — 同一个城市的 US AQI，按四级配色（<50 绿、<100 黄、<150 橙、再高是红）。
- **小灵岛表情** — 只有两只眼睛：没有脸、没有腮红、不带颜色。32 dp，2.4 秒一个情绪槽决定圆眼还是弯眼
  微笑，1.7 秒眨一次眼、其中四分之一跳过，每次眨完弹一下，每 1.2 秒换个方向看，所以真的看得见它在动。
  是在代码里近似画的，不是原素材。
- **每日一句** — 一行励志句子，宋体加粗 17.5sp；索引是「自纪元起的天数 × 7 mod 30」，每天换一句，
  也不会按顺序一句句走。
- **蓝牙电量** — 和胶囊上一样的百分比，只走被动读取：常驻这一条绝不开 GATT 连接，4 秒刷新一次也不会
  把连着的耳机打断。
- **双击复制** — 双击桌面常驻条只复制每日一句那一句，不多一个字；双击取件码卡片只复制码本身，不带
  「驿站名：」前缀。其它卡片双击不复制。

五项各占一行：开关、名字、上移、下移，都排在总开关下面，所以不想看哪一项直接关掉，不用调顺序。同时
有通知卡片时，两者每 3 秒轮换一次；手动关掉那条通知，就只剩常驻。歌词优先级更高：歌词条一直占着，
来了通知只让位 3 秒，然后按歌曲已经走到的时间点接回去。桌面不再是前台、或锁屏时，胶囊立刻消失。

### 外观

设置页最上面是「外观」卡片：八个深色色板 + 一个 0–100% 的不透明度滑杆，两个窗口同时生效——弹出的卡片
和桌面常驻条——所以两边不会一个亮一个暗。描边跟着填充一起淡下去，否则半透明的岛配一圈实心边像线框。
色板只给深色是有意的：岛上的字全是白的，浅底会直接看不清，想让它低调请用不透明度。拖动滑杆就是即时
预览。

## 怎么实现的

- `IslandService`（`IslandService.java`）是前台服务，持有一个 `TYPE_APPLICATION_OVERLAY`
  窗口，桌面常驻再额外一个。两个窗口都是 `WRAP_CONTENT`，所以缩放靠动画布局参数，
  `Gravity.TOP | CENTER_HORIZONTAL` 保证居中。
- `IslandListener`（`IslandListener.java`）是 `NotificationListenerService`：丢掉分组摘要、
  常驻通知和自己的状态通知，把标题、正文、图标和点击意图交给小灵岛。
- `SmsReceiver`（`SmsReceiver.java`）监听 `SMS_RECEIVED`，这样短信应用不发通知也能拿到验证码；
  普通短信直接丢掉。它有效时，短信应用自己那条通知会被跳过，避免同一个验证码出现两次。
- `PhoneWatcher`（`PhoneWatcher.java`）注册通话状态回调，Android 12+ 用 `TelephonyCallback`，
  更低的版本用旧的 `PhoneStateListener`。只有旧接口还带号码，所以新系统上是「未知号码」。
- `AlarmWatcher`（`AlarmWatcher.java`）读 `AlarmManager.getNextAlarmClock()`，提前十五分钟挂一次
  非精确唤醒，由它弹出闹钟卡片。系统说闹钟变了就重新排，闹钟时间过一分钟再挂一次唤醒把卡片撤掉，
  而且每次调用都拿卡片和现实对一次账：系统不再报这个闹钟，卡片就删掉。
- 卡片只从白名单点到的来源构建；旧的地图应用白名单（`IslandListener.NAV_PACKAGES`）不再参与判断，因为
  导航在 2.10 里删掉了。
- `ContentParser`（`ContentParser.java`）是分类器：关键词加正则，负责验证码、取件码和外卖时间。
- `IslandView` 用纯系统控件只画一颗胶囊：高度固定 46 dp，宽度按每张卡片重新测量，外卖长一点、取件码短
  一点。`OvershootInterpolator` 给宽度变化那点回弹。这个高度只放得下两行，所以取件码进标题行、倒计时顶替
  正文行。
- `BtWatcher`（`BtWatcher.java`）监听隐藏的 `BATTERY_LEVEL_CHANGED`，按设备地址把最后一次电量存进
  `SharedPreferences`，并用 `BluetoothManager.getConnectedDevices` 读 `GATT` 和 `HEADSET` 两个
  配置下已连接的设备。每一步都包在 try/catch 里：没有 `BLUETOOTH_CONNECT` 时返回空，而不是把
  悬浮窗搞崩。
- `StandbyView`（`StandbyView.java`）画桌面常驻那一条，并负责那两次查询：先用地名服务
  （`geocoding-api.open-meteo.com`）把城市名换成经纬度，再请求
  `api.open-meteo.com/v1/forecast?current=temperature_2m,weather_code` 拿气温和决定图标的 WMO 代码，
  需要 AQI 时再请求 `air-quality-api.open-meteo.com/v1/air-quality?current=us_aqi`。6 秒超时、同时只允许一个请求在飞、没填城市就一次都不请求。返回非 2xx 时带着状态码抛错，不再
  把空字符串丢给解析器；最近一次结果存成一句话显示在城市下面（「立即测试天气」当场发一次请求）。
  成功一次就把读数写进本机——气温、WMO 代码、AQI、解析到的地名和坐标，连城市名和抓取时间一起
  存——所以进程被杀之后先显示上次的读数，而不是空着等下一次请求；超过 12 小时的记录直接丢掉。
  坐标也从这份记录里复用，平常那一次刷新只需一个请求而不是两个。失败后按 90 秒、3 分钟、10 分钟、
  30 分钟逐级退避，不再固定 90 秒；只答了一半（有气温没 AQI）时用旧值补齐，而不是把已有的数字清空。
  `xiaoldaoView`（`xiaoldaoView.java`）只画两只
  眼睛：表情取自 2.4 秒情绪槽的哈希（圆眼或弯眼微笑），眨眼取自 1.7 秒槽的另一个哈希（四分之一跳过、
  眨完弹一下），扫视方向取自 1.2 秒槽的第三个哈希，丢帧不影响节奏，也不存任何状态。
- `IslandBridge` 是同进程内各组件之间一个静态、弱引用的总线。
- `MediaWatcher`（`MediaWatcher.java`）通过 `MediaSessionManager` 读正在播放的会话，走的是 App 早就
  拿到的通知使用权。切歌靠 `MediaController.Callback`，不轮询元数据。唯一的定时器是 2.5 秒一次的
  `UsageEvents` 查询，把前台包名和所有 `CATEGORY_HOME` 处理者比对——不是桌面就把横条收起来——并且
  只在有会话播放时跑：暂停、息屏、没给使用情况访问权限都会停掉它。一首歌一张卡片。
- `Prefs`（`Prefs.java`）是开关存储：一级功能各一个布尔值（`on_wechat`、`on_qq`、`on_pickup`、
  `on_delivery` 加 `dl_meituan` / `dl_shangou` / `dl_jd` / `dl_qixian`、`on_todo`、`on_call`、
  `on_alarm`、`on_music` 配 `on_lyrics`、`on_bt` 配每台设备一个 `bt_ok:<地址>`），`on_standby` 加五个
  子开关和一个顺序字符串管桌面常驻，另有手填的城市名和两个外观值 `look_color`（`#RRGGBB`）与
  `look_alpha`（`0`–`100`）。`IslandService.allow()` 是白名单：先决定这条事件能不能存在，再由
  `Prefs.enabled()` 丢掉自己关掉的卡片，两者都在碰悬浮窗之前。
- `Look`（`Look.java`）存这两个外观值，并把它们变成 drawable 要的东西：带上不透明度的底色，和一条跟着
  一起变淡的描边。两个悬浮窗在创建时读一次，之后在 `ACTION_LOOK` 时再读——设置页每动一下滑杆就发一次——
  所以改完两个窗口同时变；服务没开时请求直接丢掉，不会顺手把服务拉起来。
- `Lyric` 解析 LRC（`[mm:ss.cc]` 每行一条，制作信息行过滤掉），用二分查找回答「这个位置该显示哪句」；
  `LyricSource` 每首歌只做一次 HTTPS 请求，6 秒超时、512 KB 上限、16 条内存缓存。

交互：胶囊只有一个形态——贴在状态栏下方、水平居中、高度固定 46 dp，宽度随内容变长变短，外卖长、取件码
短；没有展开，也没有收起。

- **单击**打开这张卡片对应的东西：闹钟卡片打开时钟的闹钟列表，取件码打开那条短信会话。
- **双击**复制，只对两类内容有效：取件码（只复制码本身，不带「驿站名：」前缀）和桌面常驻条的每日一句
  （只复制那一句）。其它卡片双击不复制。
- **左滑**永久关闭这一条：同一条通知之后再也不会重新上岛，服务重启也不会。音乐卡片是唯一的例外——只丢掉
  当前这张，下一首照常显示；左滑闹钟卡片还会同时取消这一次闹钟后面还没出现的提醒档位。
- **不长按、直接上滑**翻看正在轮换的内容：多个取件码或通知之间、通知与桌面常驻条之间、播放音乐时在歌词
  与通知之间切换。
- **长按**时胶囊开始抖动，这时**上滑**让小灵岛消失 3 分钟，3 分钟后自己回来。
- **免打扰**（免打扰 / 仅优先 / 静音）期间，通知、取件码、外卖、待办、来电、闹钟一律不上岛；桌面常驻条
  和歌词不受影响；免打扰结束也不补弹被压下去的卡片。
- 在别的应用（非桌面）里收到的卡片直接丢弃，回到桌面也不补；这条依赖「使用情况访问」权限，没有该权限时
  退回旧行为：任何界面都弹。
- 小米时钟 App 自己发的通知（如「作息提醒 / 该睡觉了」）不上岛。
- 闹钟提醒节奏是 T-10、T-5、T-1 分钟各一次，每次显示 5 秒，之后回到桌面常驻条；正在播放音乐时直接回到
  歌词。T 之后不再提醒，系统闹钟自己会响。

把通知从通知栏划掉，小灵岛同样会消失。音乐卡片不计时收起：它一直开着，逐字歌词才有意义；只有停止播放、
你手动划掉、或有别的应用到前台时才收。回到桌面会立刻回来：前台结论是缓存的，因为 `UsageEvents` 报的是
「变化」，空窗口意味着「什么都没动」而不是「什么都不在前台」——按后者解释，卡片出现几秒后就自己消失了。
歌词那一行也只在
播放器可信的范围内相信它：`getLastPositionUpdateTime()` 合理时才做位置外推；上报位置和运行的估算
偏差超过 700 毫秒就重新对齐；LRC 的 `[offset:±ms]` 会应用；整首歌词总长和曲目时长差太远（不是同一个
录音）就整份丢掉，而不是放到对不上的位置。

## 开关

App 里是一个两级列表，一级开关从上到下共九个：

| 一级开关 | 默认 | 二级开关（只在父开关打开时出现） |
|---|---|---|
| 微信 | 开 | — |
| QQ | 开 | — |
| 短信取件码 | 开 | — |
| 外卖进度 | 开 | 美团、闪购、京东、七鲜，各管各的预计到达时间卡片 |
| 待办提醒 | 开 | — |
| 来电显示 | 开 | — |
| 闹钟 | 开 | — |
| 音乐播放与歌词 | 开 | 联网歌词——每首歌那一次歌词请求 |
| 自动更新 | 关 | 每小时问一次 `api.github.com`，有新版就下载并交给系统安装器 |

二级只在父开关打开时存在：父开关一关，子列表折叠、里面的行整个丢掉，不会在关掉的开关下面留着半截
界面。这张表以外的东西全部删掉了，连带三类卡片：**普通通知、验证码、导航不再上岛。**
`IslandService.allow()` 是白名单，不在表里的 App 一律弹不出来。外卖卡片属于哪个平台先看包名
（`sankuai`/`meituan`、`jingdong`/`com.jd.*`、`shangou`、`qixian`），再看卡片上的文字，因为七鲜装在
`com.jd.*` 包里；认不出来的平台放行，宁可多显示一行也不漏单。这张卡片以外还有：

| 开关 | 默认 | 作用 |
|---|---|---|
| 桌面常驻 | 关 | 桌面上的那条窄胶囊 |
| 天气温度 / 空气质量 AQI / 小灵岛表情 / 每日一句 / 蓝牙电量 | 开 | 桌面常驻里包含哪几项；每项一行，各自一个开关 |
| 城市 | 空 | 不填城市就完全不发天气请求；可以填到区（「北京 朝阳」） |

## 需要你自己开的权限

1. **显示在其他应用上层**（`SYSTEM_ALERT_WINDOW`），悬浮窗本体。
2. **通知使用权**（`BIND_NOTIFICATION_LISTENER_SERVICE`），卡片内容来源。
3. **短信**（`RECEIVE_SMS`），可选：给不落到通知栏的验证码用。
4. **电话**（`READ_PHONE_STATE`），可选：来电卡片。Android 12+ 上卡片仍然写「未知号码」，
   因为号码不再提供给第三方应用。
5. **使用情况访问**（`PACKAGE_USAGE_STATS`），可选，但「只在桌面显示」和桌面常驻都靠它判断前台。
   播歌时每 2.5 秒一次查询，桌面常驻生效时每 4 秒一次。
6. **附近设备**（`BLUETOOTH_CONNECT`、`BLUETOOTH_SCAN`）在 2.16 之前是配件电量要用的；2.16 把功能
   和这两个权限一起删掉了。
7. MIUI / HyperOS 还要给这个 App 开 **后台弹出界面**，否则系统会把后台发起的悬浮窗丢掉。
8. Android 13+ 会问 `POST_NOTIFICATIONS`，前台服务的状态通知要用。
9. **电池优化**（`REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`，可选），再加 MIUI 的「自启动」、「省电策略 →
   无限制」、设置 → 省电与电池 →「锁屏后清理内存」设为「永不」，最近任务里下拉加锁也有效。
   Android 12 起禁止后台启动前台服务，而且被拒时不报错，所以复活现在走两只钟：任务被划掉时（以及
   服务在开关还开着的情况下被销毁）排一个**8 秒后的闹钟**，再排一个 10 秒后的持久化一次性 job，
   15 分钟看门狗最后兜底。闹钟才是可靠的那条：广播投递会给应用几秒的临时白名单，正好够它把前台
   服务拉起来。被拒的那次不会被丢掉，按 30 秒、60 秒、3 分钟、10 分钟重试，之后每 15 分钟一次。
   「后台常驻」卡片上的按钮直接跳到 MIUI 自启动页（跳不过去就退回应用详情页）；下面新增的
   「保活诊断」卡片打印最近六十条记录——任务被划掉、闹钟触发、启动被拒、常驻岛为什么被隐藏——
   并带一个复制按钮，因为「它就是没回来」这种事不该靠回忆描述。另外，如果用量事件突然断了，
   「别的应用在前台」这个判断超过两分钟没被刷新就会被丢掉、回到安全默认值，而不是让药丸一整天
   都不出现。开机恢复靠 `RECEIVE_BOOT_COMPLETED`（不弹窗），且只在上次是开着的时候恢复。
   手动「强行停止」仍然会清掉一切：应用排的任何任务都活不过它，这是系统的设计，不是 bug。
10. **安装未知应用**（`REQUEST_INSTALL_PACKAGES`），只给更新用：检查更新下好的包交给系统安装器，
   而系统不允许一个没有这个授权的应用唤起安装器。最后一下仍然是你点，这里不会自己装。

## 它做不到什么

- 不是 `SystemUI` 插件。画不到状态栏上面（状态栏是更高层的窗口），所以小灵岛贴在状态栏下面，
  而不是套在挖孔周围。
- 和锁屏没有交互：锁屏时系统会隐藏 `TYPE_APPLICATION_OVERLAY` 窗口。
- 待办卡片只能看到小米笔记的**提醒通知**。读笔记数据库本身需要 root，也没有公开 provider，
  所以小灵岛列不出待办清单。
- 来电卡片在 Android 12+ 显示不了号码：系统不再把号码给第三方应用。而且通话界面是全屏 Activity，
  真正响铃时它会盖住悬浮窗。
- 闹钟卡片是提前十五分钟的提醒；闹钟响时，时钟应用的全屏意图会盖住一切。卡片在闹钟时间过一分钟后
  撤回，`AlarmWatcher.schedule` 一发现 `getNextAlarmClock()` 不再报那个闹钟也会立刻收回，所以提醒不会
  活得比闹钟还久。同一个闹钟只播报一次：触发时间记在 `Prefs.KEY_ALARM_SHOWN`。如果某个 ROM 一直报
  一个时钟应用里已经没有的闹钟，那还是会多出一张卡片——「闹钟」开关就是出口。
- 普通通知、验证码、导航在 2.10 里被整体删掉了：这是按需求做的删除，不是失灵——岛只从上面那张白名单
  里出卡片。
- 音乐显示的是播放器自己公开的东西。真正的逐行歌词离线拿不到：网易云音乐把歌词放在自己的界面里，
  媒体会话里什么都没有；而那个界面在前台时卡片本来就该隐藏。所以歌词来自 `music.163.com` 的公开
  接口，HTTPS、每首歌一次、只在「联网歌词」开着时、512 KB 上限、只放内存。那个接口每行一个时间戳，
  不是每个字，所以逐字点亮是在一行之内做线性插值：它告诉你正在唱哪一句、大概唱到这句的什么位置，
  不是逐字精确。查不到或开关关着时，那一行显示歌名。
- 音乐横条和桌面常驻都**只在桌面显示**，并且需要**使用情况访问**权限：拿不到权限时 App 分不清桌面
  和应用，横条会退化成在任何界面都显示，桌面常驻则完全不出现。
- 气温和 AQI 要你手填城市，并且会请求 Open-Meteo 的两个域名：`api.open-meteo.com` 拿预报、
  `air-quality-api.open-meteo.com` 拿空气质量，地名解析走 `geocoding-api.open-meteo.com`。
- 「自动更新」默认关着，「检查更新」按钮则是手动做同一件事。两者都走同一条路：读
  `Kreston8/xiaoldao` 的 release 列表（`api.github.com/repos/Kreston8/xiaoldao/releases?per_page=50`），
  拿最新的 `xiaoldao-v…` 标签和已安装的 `versionName` 比大小；只有更新的标签才会去
  `objects.githubusercontent.com` 把这个版本的 `.apk` 下到应用自己的缓存目录，再经一个只提供这一个
  文件的 content provider 交给系统安装器。三件必须说清楚的事：一、检查只在岛的服务活着时发生；
  二、检查失败会写进「保活诊断」，不会变成按了没反应；三、没有静默安装——没有 root 或 device owner
  权限，最后一下必须你自己点，而且第一次还要在系统设置里给本应用「安装未知应用」。
- `BLUETOOTH_CONNECT` 和配件电量已经随 2.16 一起删掉了：公开接口给不出可靠数字，宁可删掉也不猜。

## 构建

本机需要 JDK 17 和 Android SDK（`compileSdk 34`）：

```bash
cd android
gradle assembleRelease
# android/app/build/outputs/apk/release/app-release.apk
```

签名是钉死的：`app/build.gradle.kts` 读 `ANDROID_KEYSTORE_PATH`、`ANDROID_KEYSTORE_PASSWORD`、
`ANDROID_KEY_ALIAS`、`ANDROID_KEY_PASSWORD`，有就用那个 PKCS12 密钥库，所以相邻版本能互相覆盖安装。
没有就退回 debug 签名，那种包必须先卸载。密钥不在仓库里：它在仓库 secrets 和维护者的离线备份里，
丢了的代价就是再多卸载一次。

也可以往 `android-apk` 分支推一次，或手动跑 **Build Android APK** 工作流：它构建 APK 并挂到一个
GitHub Release 上。

## 装到手机上

1. 从 Release 附件里下载 `.apk`。
2. 给你用来下载的那个应用开「安装未知应用」（MIUI：设置 → 应用设置 → 特殊权限 → 安装未知应用）。
3. 打开 App，把权限开好，点「启动小灵岛」，再点「预览效果」。

## 版本号怎么长的

`versionName` 是 `2.<批次>.<run>`，`versionCode` 就是工作流的 run number，Release tag 是
`xiaoldao-v2.<批次>.<run>`。中间那位每批功能加一，所以发出来的版本号会跳号：失败的 run 不发版，
而每批新功能都故意换一次中间位。

## 该下哪个包

只有一个包，没得选：App 是纯 Java，全在 `classes.dex` 里，没有 native 代码，所以没有 `lib/` 目录，
也就没有按 ABI 分包这回事；真正和设备相关的判断都在运行时做（桌面包名靠 `CATEGORY_HOME` 解析，
前台包名靠 `UsageEvents`）。`minSdk 26` 表示 Android 8.0 及以上；`compileSdk`/`targetSdk 34` 表示
按 Android 14 编译和校验。这一个文件能装在 MIUI 12-14 或 HyperOS 的小米 / 红米 / POCO 上，也能装在
别的系统上，前提是接受上面那些限制。

按系统分开发布只是打包表演：这些手机的差别在于用户给不给权限、以及运行时的探测，不是能被编译掉的代码。
